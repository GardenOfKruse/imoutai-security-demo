# 项目协作规则

## 项目性质与授权范围

本项目是公司内部安全团队针对指定 Android 样本开展的安全测试与验证项目。当前目标样本为 i茅台 v1.9.12（`com.moutai.mall`，versionCode 10912），测试设备与授权范围以本目录 `scope.md` 为准。

在该授权范围内，Agent 可以自主推进 APK 解包、静态反编译、DEX/so 分析、Frida 动态插桩、运行时证据采集、网络边界观察和离线签名验证，并按适用的逆向技能选择工具和切换路线。每个已通过步骤都追加到 `notes/steps-log.md`，记录可复现命令、产物和证据；失败尝试单独归类。

## 数据与网络边界

- 网络画像以 `scope.md` 为准（当前 `authorized_target_only`：仅限 `h5.moutai519.com.cn` / `app.moutai519.com.cn`，客户自有系统）。
- 登录测试仅使用本人测试账号；手机号、token、验证码、Cookie 和设备标识在日志与抓包落盘前脱敏。
- 不进行撞库、不利用验证码绕过实施批量账号操作或刷接口（验证码机制还原仅用于风控能力评估、授权窗口内的低频测试与培训演示）。
- 不读取、输出或提交未脱敏的凭据、令牌或客户数据。
- `scope.md` 是授权范围依据，修改须由操作者确认并记录到 `notes/steps-log.md`。

## ⛔ 生产交互硬门禁（当前验证阶段，Agent 不得违反）

> 当前处于**验证阶段**（Phase 0 离线准备）。以下规则为硬性约束，任何 Agent 会话、任何模型、任何理由都不得突破；违反即任务失败。

1. **单进程硬限制**：一切涉及目标系统请求的验证/测试动作，只允许 **1 个工作进程**串行执行。禁止任何形式的并发、多进程、多设备协同施压——否则会造成产线不稳定。
2. **本地离线优先**：验证阶段所有签名/请求构造研究在本地完成（离线比对、只读 hook 采集），**不发任何构造请求到生产**。
3. **离线验证门禁**：签名构造器未经离线逐字节验证 PASS 之前，禁止向生产发送任何请求。
4. **生产请求仅限维护窗口之外的低频 runbook**（`notes/next-phase-plan-purchase-info-v2.md` §3）。
   - **客户最新确认（2026-09-12）**：除 **06:00 – 06:15** 外，其余时间均可执行本演示项目测试；
   - **维护窗口禁止任何生产请求**：**06:00 – 06:15**——客户在该时段有维护安排；
   - 允许多次低频执行，但每次执行必须保持单进程串行、请求间隔 ≥2 秒、请求总量 ≤300、时长 ≤30 分钟、止步支付页；禁止大并发、高频刷接口和多进程协同。五条中止条件（5xx>1%、p95 劣化 3 倍、限流误伤迹象、客户叫停、预算耗尽）任一触发立即停止。
   - Agent 发起任何生产请求前必须校验当前本地时间不在 06:00–06:15；维护窗口内请求一律拒绝执行。
5. **灰度确认**：进入任何生产请求前，必须由操作者（人）明确确认窗口时段与账号就绪；Agent 不得自行发起生产请求。
5a. **实弹全真实原则（客户明确要求，2026-09-12）**：实弹模式下的每一笔请求（登录、下单、验证码交互等）必须使用真实环境、产生真实业务数据、执行真实业务步骤——**禁止任何模拟标记/测试痕迹进入真实请求**（User-Agent、头、参数均按真实 App 形态构造）。原因：本次测试的核心结论就是"协议级复刻的请求与正常用户无法区分、后台无异常可查"；任何模拟痕迹都会污染该结论。演示叙事用的"自动识别动画"只存在于 Mock 模式，绝不进入实弹请求流。
6. **证据留痕**：生产窗口的每个请求记录时间戳、用例编号、响应摘要（脱敏）；执行前后在 `notes/steps-log.md` 记录。

## 💳 支付红线（永久有效，任何阶段不得违反）

- 支付链接/scheme（支付宝、微信支付、银联等）**只做拼接算法的静态还原**（JS/App 代码分析、字符串模板拼接逻辑整理）。
- **绝对禁止**对任何支付链接发起真实调用：不 HTTP 请求、不浏览器打开、不 scheme 唤醒、不重放支付参数——防止破坏线上账务信息。
- 本目标产出仅为：支付链接拼接逻辑文档 + **用户安全支付建议**（给开发者的防御输入）。
- 涉及支付的所有文档/演示必须带此红线声明。

## 🔁 自动化工具边界

- 允许将**已通过校验的步骤**固化为自动化脚本（接口签名构造器、登录态保持、请求构造模板），避免重复验证已通过的测试用例。
- 自动化产物仅用于：授权窗口内的 runbook 执行 + 离线演示；窗口外一律不运行其对生产部分。
- 自动化脚本必须内置：单进程、窗口时间校验、请求计数、中止条件（复用 AGENTS.md 硬门禁）。
