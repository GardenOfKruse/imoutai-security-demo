签名算法破解：短信验证码 md5（已逐字节验证）

cracked via 运行时本地采样（15/15 逐字节 PASS）。调用链：LoginActivity.getVerifyRequest → com.netease.libs.yxsecurity.encrypt.CryptoUtil.l → o → MessageDigest(MD5)
md5 = MD5( deviceKey + mobile + timestamp )15/15 PASS
deviceKey = 设备绑定 32 位 hex（本设备样本 2af72f100c356273d46284f6fd1dfc08，跨会话稳定）；mobile 为明文手机号；timestamp 为毫秒时间戳字符串。无盐混淆、无 HMAC、无 nonce 防重放。
🧮 交互式签名计算器（离线演示，与真实样本逐字节一致）
拼接明文
MD5 结果 vs 期望
攻击含义：三个输入对攻击者全部可得（deviceKey 可同机读取/一次抓包获得）→ 可离线批量构造合法验证码请求。防御含义：签名输入含手机号明文 + 时间戳跨度长 + 无服务端 nonce，重放窗口大。

壳绕过方法论：打不穿壳，就绕开壳

梆梆三层防护：SecShell 全加密壳 + DexVMP 方法虚拟化 + Everisk 风控熔断。传统脱壳路线（spawn 注入/内存扫描/dexdump）全部失败，最终采用「运行态反射」路线。
静态定性（10 分钟）

解包识别 libDexHelper.so + libdexvmp.so + RiskStub.dex、StubApplication=com.secneo.apkwrapper.AW → 判定全加密壳，业务 dex 运行时解密，静态路线死刑。

延迟附加（核心突破）

正常启动 App，T+4~6 秒后 Frida 附加（非 spawn）——等壳完成解密加载后再进场，避开壳初始化期的全部自检（JNI_OnLoad 校验、namespace 检查、反调试线程）。

纯反射 dump（零 hook、最小足迹）

enumerateLoadedClassesSync 过滤业务包 → getDeclaredMethods / Annotations / ParameterAnnotations / Fields。Retrofit 注解直接暴露全部接口 URL 与参数注解。220 类 0 失败，全程不需要 dex 文件本体。

熔断应对：快进快出

Everisk 检测 root 后启动 ~30-48 秒倒计时自杀（与注入无关）。应对：不对抗退出逻辑，把采集压缩进窗口、每类数据独立落盘、T+25s 前主动 detach。

运行时采样 → 一锤定音

区分「纯工厂方法」（可安全本地调用）→ Java.choose 取活实例采样 (mobile,timestamp,md5) 三元组 → hook MessageDigest.update/digest 捕获喂进哈希的原始字节——拼接串和设备 key 直接现形。

给开发者的关键结论：壳能挡住「长驻注入」，挡不住「快进快出的反射读取」；能延迟解密，挡不住「运行态元数据枚举」。防御必须假设运行态接口元数据已泄露。

防御建议（给 APP 开发者，按优先级）

P0 · 立即

验证码签名重设计

当前 md5(deviceKey+mobile+ts) 无盐、无 HMAC、无 nonce。改为 HMAC-SHA256 + 服务端下发一次性 challenge（nonce）+ 收紧时间窗（±60s）+ 服务端频率限制。

P0 · 立即

设备密钥不可导出

deviceKey/RSA 私钥运行时可被同机读取或 hook 导出。密钥改为每会话服务端协商下发、绑定会话有效期；native 层增加调用环境校验。

P1 · 短期

签名实现去中心化

签名构造集中在单个 Java 工厂方法（一次反射调用即可批量采样）。拆散调用链、下沉 native、关键请求加时间戳+序列号服务端去重。

P1 · 短期

风控信号上报替代客户端自杀

Everisk 熔断自杀只防「长驻注入」，防不住快进快出。改为：客户端只上报原始信号，服务端聚合判定 + 静默降级 + 会话标记，让攻击者无法通过「快速完成」绕过。

P1 · 短期

接口元数据混淆

Retrofit 注解明文暴露全部接口与参数结构。建议对 H5/API 文档化面做收敛：非必要字段不出现在注解、路径版本化、按端最小暴露。

P2 · 规划

行为风控强化

Everisk 已有触摸/传感器遥测（scene=login）。建议服务端利用行为序列做自动化识别，验证码人机校验前置到下单/预约等高价值写接口。
